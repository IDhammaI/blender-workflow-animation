# 运行时接入参考

## 整幅 Blender 视频

页面组件保持一个固定比例的场景容器，静帧始终在底层，视频播放成功后再显示。视频建议使用以下属性：

```tsx
<video
  src={source}
  poster={poster}
  muted
  loop
  playsInline
  preload="auto"
  onPlaying={() => setReady(true)}
  onError={() => setReady(false)}
/>
```

实现时还要：

- 在 `prefers-reduced-motion: reduce` 或窄屏时不挂载视频；
- 页面进入后台时暂停，回到前台再尝试播放；
- 自动播放被浏览器拒绝时保留静帧，不弹出阻断性错误；
- 深浅主题切换时卸载旧视频并加载新资源，避免旧帧短暂闪现；
- source 改变时重置 ready 状态，清理旧的 `play()` promise、事件监听和 media query listener，避免迟到的旧视频事件把旧帧重新显示；
- 装饰动画不读取或写入登录表单、会话和业务数据。

实际页面验收至少覆盖：浅色、深色和主题切换；poster 布局稳定；慢网络、404 和自动播放拒绝；后台暂停/恢复；`prefers-reduced-motion`；768px 边界和窄屏；错误日志为空；部署 base path 下的资源路径正确。验证视频大小、poster 大小和首屏加载时间，不用无限重试修复资源失败。

## 分层动画

当用户需要独立控制候选卡、屏幕消息或状态灯时，将 Blender 输出拆成固定底座、动态前景和投影层。固定层可以是 WebP/SVG，短片段或 Canvas 负责动态内容，页面只提供虚构的显示数据。

分层时锁定每层的画布尺寸、坐标原点和透明边距；浅深主题使用同一几何布局，只替换主题素材。不要让一套 Lottie、CSS keyframes 和视频同时控制同一个对象。

为每次媒体变更生成 revision 或 hash，并让代码中的资源 manifest、视频、poster 和 `.blend` 使用同一版本标识，避免浏览器或 CDN 继续拿旧资源。

## 透明 Logo 加载动画

整幅登录页视频和启动加载动画是两个组件：

1. Blender 分别导出透明 Logo 本体和投影图集；
2. Canvas 按帧绘制本体和投影，投影先画；
3. 组件设置独立加载超时、完整播放时长和静态 Logo 回退；
4. 完成回调只发送一次，不能因为 StrictMode、资源失败或后台暂停重复触发；
5. `prefers-reduced-motion` 时直接显示静态标志。

## 交付边界

如果只制作预览，不修改页面资源或代码；如果接入网页，说明实际替换了哪些资源、是否需要刷新或重启、视频和静帧的路径、验证过的主题和响应式范围。不要把“成功渲染视频”描述成“已经部署”或“已经完成真实业务验证”。

外部贴图、字体、品牌图标和生成素材要记录来源与许可；交付前做一次去敏检查，确保没有真实候选人、聊天内容、凭据或平台页面截图进入素材包。
