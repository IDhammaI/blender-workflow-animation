# Blender 界面工作流动画制作参考

这份流程提取自一套“业务信息从来源流向处理区和结果区”的 3D 登录页样片。名称、数量和画面内容只是示例；复用时替换为当前产品的虚构装饰信息。

## 场景分层

建议先建立以下层级，再开始插关键帧：

```text
场景
├─ 固定底座与背板
├─ 来源模块（平台标牌、消息卡）
├─ 实体模块（队列、头像、资料卡）
├─ 处理模块（标题、分类方标、信息条）
├─ 工作区模块（桌面、显示器、人物、键鼠）
├─ 结果模块（任务、归档、审核）
└─ 数据路径与光点
```

每个模块的内容放在独立父级，底座使用相邻但独立的对象。这样可以让卡片轻抬、资料线绘制或消息气泡缩放，而不让承载它们的平台移动。为固定对象维护一个 manifest（对象名、集合、父级、预期变换和是否允许可见性变化）；缺失或多出的固定对象应让检查失败，而不是静默继续。

复杂场景可以按阶段保存：先保存已确认的桌面和人物，再加入候选卡、岗位卡和来源消息，最后才编排数据路径、结果节点和屏幕细节。每个阶段都应有静帧和检查脚本，下一阶段只加载通过审阅的 `.blend`，避免把未确认的造型和动效一起放大。

## 时间线设计

常见的 24 fps 方案是 4 秒入场（96 帧）加 8 秒循环（192 帧），也可以按展示区域和文件大小调整。不要把这些数字当成硬编码；重要的是把入场边界、循环边界和页面退出时机分别定义。

- 入场：来源卡片、候选队列、岗位、人物工作区和结果节点错峰出现，使用缓入缓出或三次减速落定。
- 循环：来源到候选人、候选人到工作区、岗位到工作区、工作区到结果、结果到归档和归档到审核按顺序流动。
- 屏幕：资料线先收回再逐项载入；头像提示环、搜索图标、消息气泡、输入圆点和完成按钮各有独立父级。
- 人物：只做小幅交替打字或手部运动；头发、桌椅、显示器外壳和底座保持稳定。
- 勾线：用曲线 `bevel_factor_end` 或等效属性分阶段绘制，保持静止时的完整勾号。

不要让循环最后一帧重复第一帧。若循环状态定义在 1 和 193 帧，视频应渲染 1–192 帧；在 Python 中可用 `phase = frame % 192` 让首尾使用相同相位。

## 建模和材质规则

- 先锁定相机、正交缩放和主要空间方向，再调材质；不要用改相机来掩盖遮挡问题。
- 复用已确认的卡片、平台、头像和品牌图标。若依赖外部图片，先裁切、校正比例并随 `.blend` 保存。
- 字体和必要的矢量字标在交付场景中转为几何，避免换机器缺字体。
- 真实品牌图标可以作为装饰素材使用；不因为画面出现图标就宣称接入新的平台。
- 浅色和深色使用独立材质与灯光。深色场景应保留人物衣服、桌面、屏幕和卡片的明暗层次，不能只压暗曝光。

## 可复现环境契约

交付前记录 Blender 主版本、渲染引擎、色彩管理/视图变换、场景单位、相机参数、输出分辨率和 GPU/CPU 回退方式。生成入口应接受输入 `.blend`、素材目录和输出目录参数，不能依赖当前机器的工作目录或临时绝对路径。

输入素材至少包括：源 `.blend`、脚本、贴图、字体或字体转几何后的结果、品牌图标来源、渲染命令和版本标识。把这些与输出 manifest 放在同一交付目录，才能让另一台机器重跑或定位差异。

## 循环确定性检查

渲染前在 Blender Python 中做至少这些检查：

```python
# 1. 循环状态相同：对象变换、曲线绘制、形态键和关键材质值
assert max(abs(a - b) for a, b in zip(snapshot(1), snapshot(loop_end + 1))) < 1e-5

# 2. 固定层没有动画
assert all(obj.animation_data is None for obj in fixed_objects)

# 3. 固定层每帧位置不变
baseline = {obj.name: obj.matrix_world.copy() for obj in fixed_objects}
for frame in range(1, loop_end + 2):
    scene.frame_set(frame)
    assert all(obj.matrix_world == baseline[obj.name] for obj in fixed_objects)
```

snapshot 不应只收集普通对象变换；若场景使用这些属性，也要纳入比较：相机、灯光 energy、世界背景、合成节点、材质透明/发光值、贴图槽和 render visibility。浅深主题还要比较对象 ID 集合、关键帧边界和固定 manifest，确保深色脚本没有漏掉新对象或改变时序。

实际项目还应抽查：

- 光点是否在节点边界前淡出，是否穿透卡片或显示器；
- 搜索图标、消息气泡和输入点是否始终落在屏幕内；
- 淡入材质是否产生黑色残影、透明排序错误或投影方框；
- 主题切换后屏幕文字、人物轮廓和地面反射是否仍然可读；
- 首帧、循环末帧和重播首帧是否肉眼连续。

屏幕内对象应先投影到屏幕平面，再对逐帧 bounding box 做安全区断言；只看一张截图不足以发现消息气泡或搜索图标在中间帧穿出屏幕。

如果使用材质发光、面光或世界光的 driver，渲染前把 driver 烘焙为关键帧，再重新打开保存后的 `.blend` 检查 driver 已清空、亮度关键帧仍存在。否则换机器或运行时重载场景后，发光可能丢失或与静帧不一致。

## 媒体级检查

除了场景状态检查，还要用实际媒体读取器或浏览器检查：

- 分辨率、帧率、总帧数、时长和 H.264 解码；
- 首帧与下一轮首帧的像素差，不能因为重复末帧或背景融合产生跳变；
- 全片是否确实有运动，避免关键帧丢失后输出静止视频；
- 浅色和深色是否共用相同构图、时序和固定底座；
- poster 与视频首帧是否一致，页面背景边缘没有黑边或矩形色块。

示例项目曾使用 192 帧、24 fps、8 秒、1920×1440，并渲染 1–192 帧、用第 193 帧做循环快照校验。这是一个可用起点，不是所有项目的固定规格。

## 输出与审阅

保留下列产物：

- `scene.blend`：可编辑源场景；
- `theme-poster.webp` 或 PNG：视频加载和失败回退使用的静帧；
- `theme.mp4`：浏览器播放版本；
- `check` 抽帧图或 HTML：便于比较关键帧、主题和首尾。

用媒体工具或浏览器实际读取输出文件，不只相信 Blender 的渲染日志。验证时记录分辨率、帧率、时长、帧数、编码、首尾差异和文件大小；同时设置视频、poster 和首屏预加载预算。仅当页面实际加载、自动播放回退和减少动态效果均通过，才算完成网页接入。

## 可复现性边界

不要只保存最终 MP4。至少把生成它的 `.blend`、脚本入口、输入素材、命令参数和检查结果一起交付。若某个“光影优化版”依赖外部可视化目录中的临时脚本，先复制出最小可运行版本或明确标注缺口；不要用硬编码的临时绝对路径、文本替换脚本或当前机器专属 GPU 设置冒充通用流程。
